# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project state

`binance-th` is a typed, async-first Python client library for the Binance **Thailand** API. It is **feature-complete at `1.0.0`** — milestones M1–M7 are implemented and merged (tracked in `docs/plans/ROADMAP.md`): the async `httpx` transport with HMAC signing / server-time offset / typed errors (M1), the dual-window rate limiter + retry (M2), the REST clients `client.market`/`account`/`wallet` (M3) and `client.orders` with pre-trade validation + UNKNOWN reconciliation (M4), the WebSocket `client.ws` market streams + self-syncing local order book (M5), and `client.user_stream` — the authenticated user-data stream with a self-healing order tracker (M6). M7 added packaging (`py.typed`, PyPI publish workflow), a weekly `bandit`/`pip-audit` security scan, and the community meta set. The public REST/WS shapes are **live-verified** (the probes under `scripts/`); the only remaining ⚠ASSUMED surface is the user-data **event shapes** (`executionReport`/`outboundAccountPosition`/`balanceUpdate`), pending the guarded `scripts/soak_userdata.py` order soak.

## Commands

This project uses **`uv`** (not pip/poetry). Python **3.12+** required (CI also runs 3.13).

```bash
uv sync --extra dev                 # install runtime + dev dependencies
uv run pytest                       # full test suite (enforces ≥90% coverage — see gotcha below)
uv run ruff format .                # auto-format (check-only: ruff format --check .)
uv run ruff check . --fix           # lint + autofix
uv run mypy binance_th              # strict type-check
uv run pre-commit run --all-files   # run every hook (ruff, ruff-format, mypy --strict, hygiene)
```

**Running a single test — important gotcha:** `[tool.pytest.ini_options] addopts` hard-codes `--cov-fail-under=90`, so running a subset makes coverage look low and pytest exits non-zero **even when the selected tests pass**. Disable coverage when running a focused test:

```bash
uv run pytest tests/test_models/test_orders.py::TestOrderRequest::test_valid_limit_order --no-cov
```

CI (`.github/workflows/ci.yml`) runs three independent jobs — lint, type-check, test — and all must pass. `mypy` is `strict = true`; `ruff` line-length is 100 with a broad ruleset (including `ASYNC`). Commits follow Conventional Commits with phase scopes, e.g. `feat(phase-01): ...`, `fix(ci): ...`.

## Architecture — the load-bearing conventions

The whole library is Pydantic v2 models today, so the conventions below are the architecture. They span files and are easy to violate:

- **Two base classes with opposite validation policies** (`models/base.py`). Every response model subclasses `ResponseModel` (`extra="allow"` — forward-compatible with new API fields Binance adds); every request model subclasses `RequestModel` (`extra="forbid"` — rejects typos before a request is sent). Both set `populate_by_name=True` and `str_strip_whitespace=True`. Pick the correct base by direction (response vs request).

- **snake_case attributes ↔ camelCase API via `Field(alias=...)`.** Python code uses `order_id`; the wire uses `orderId`. `populate_by_name=True` means models accept **either** name. When adding a field, set its `alias` to the exact API JSON key.

- **`Decimal` for all money** — prices, quantities, balances, fees, commissions. Never `float`. Stated policy in `models/base.py`.

- **Array-shaped responses need explicit parsers.** Some endpoints return positional arrays, not JSON objects, so those models are **not** constructible from a raw dict — use their classmethods: `Kline.from_list(...)`, `OrderBookEntry.from_list(...)`, `OrderBook.from_api(...)`. Add a `from_list`/`from_api` classmethod for any new array-format endpoint.

- **Request models deliberately omit `timestamp` and `signature`.** Signed-endpoint auth is auto-generated by the (future) REST client — `timestamp = now_ms + server_time_offset`, `signature = HMAC_SHA256(query_string, api_secret)`. Do **not** add these fields to `RequestModel` subclasses; users supply only business parameters. See the header docstring of `models/orders.py`.

- **Order rules live in `@model_validator(mode="after")`.** `OrderRequest` encodes Binance's constraints (LIMIT ⇒ price + timeInForce + quantity; MARKET ⇒ quantity **or** quoteOrderQty; STOP\* ⇒ stopPrice; …). `CancelOrderRequest`/`QueryOrderRequest` require `orderId` **or** `origClientOrderId`. New endpoint constraints go in a validator like these, and the tests assert on the exact `ValueError` message strings.

- **Exceptions mirror HTTP status with domain semantics** (`exceptions.py`). Root is `BinanceThError`; `BinanceThAPIError` subclasses carry `status_code` / `request_id` / `response_data`. `HTTP_STATUS_MAP` + `get_exception_for_status_code()` map a status code to a class (400→BadRequest, 401→Auth, 403→WAF, 418→IPBanned, 429→RateLimit, 5xx→Server). **Domain rule baked in:** a `BinanceThServerError` (5xx) means execution status is *unknown*, **not** failure — callers must verify order state before retrying, not assume the operation failed.

- **GLOBAL vs SITE symbols is a Binance-TH-specific split.** The `SymbolType` enum (GLOBAL vs SITE), the two WebSocket base URLs in `config.py` (`ws_base_url_global` → `/gstream`, `ws_base_url_site` → `/nstream`), and `ListenKey.symbol_type` all exist because Binance Thailand serves platform-wide vs region-specific symbols on different streams. Preserve this distinction when adding WebSocket/stream code.

- **`BinanceThConfig` is pydantic-settings** (`config.py`): reads env vars prefixed `BINANCE_TH_` and a `.env` file; `api_secret` is a `SecretStr` (use `.get_secret_value()`). REST base defaults to `https://api.binance.th`.

- **Public API is explicit.** `binance_th/__init__.py` and `binance_th/models/__init__.py` both maintain alphabetized `__all__` lists. A new public symbol must be added to its module's `__all__` **and** re-exported (and, if top-level, listed in the root `__init__`).
