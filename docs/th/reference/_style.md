# Reference style

[หน้าแรก](../index.md) > อ้างอิง > Style

[English](../../reference/_style.md) · **ไทย**

หน้าทุกหน้าใน `reference/` เขียนตามแนวนี้ ส่วนอ้างอิงคือ **ข้อกำหนด ไม่ใช่บทเรียน** — มันบอกว่าแต่ละสิ่งคืออะไร
ไม่ได้บอกว่าคุณควรรู้สึกอย่างไรกับมัน

## ลำดับหัวข้อในหน้าที่ต้องมี

1. แถบนำทาง (breadcrumb): `[หน้าแรก](../index.md) > อ้างอิง > <Name>`
2. `# <Name> Reference`
3. `**โมดูล:** \`binance_th.<module>\`` และ `**มีให้ใช้ตั้งแต่:** 1.0.0`
4. คำอธิบายคลาส/namespace แบบสั้น ๆ หนึ่งประโยค
5. `## การ import` — บรรทัดสำหรับ import
6. signature ของคลาส (constructor) ถ้าเป็นสิ่งที่ผู้ใช้สร้างเอง
7. `## เมธอด` — หนึ่ง `### <method>` ต่อหนึ่งเมธอดสาธารณะ แต่ละอันประกอบด้วย: โค้ดบล็อกของ signature,
   ตาราง **พารามิเตอร์** (พารามิเตอร์ / ชนิด / ค่าเริ่มต้น / คำอธิบาย), **คืนค่า**, **อาจยก (raises)** (ถ้ามี),
   และ **ตัวอย่าง** หนึ่งอัน
8. `## ดูเพิ่มเติม` — ลิงก์ข้ามไปหน้าอื่น พร้อมคำอธิบายกำกับด้วย em dash

## กฎการเขียน

- signature ต้องเป๊ะ คัดลอกมาจากซอร์สโดยตรง อย่าเดาชนิดของพารามิเตอร์หรือชนิดของค่าที่คืนเด็ดขาด
- ใช้ตารางกับอะไรก็ตามที่แจกแจงเป็นรายการได้ (พารามิเตอร์, field, ชนิดของ error)
- เขียนแบบตรงไปตรงมา: "คืนค่า X" "ยก `BinanceThAuthError` ถ้าไม่มีคีย์" ไม่ใช่ "ในส่วนนี้เราจะ…"
  หรือ "คุณสามารถใช้สิ่งนี้เพื่อ…"
- ชนิดข้อมูลที่เป็นเงินเป็น `Decimal` ทำเครื่องหมายเมธอดที่เป็น **signed**, **api-key-only**, หรือ **mutating**
- เก็บเนื้อหาแบบบทเรียนไว้ใน [คู่มือ](../guides/market-data.md) แล้วลิงก์ไปหา อย่าเอามาแทรกในหน้านี้
